PROJECT OVERVIEW
================================================================================
StockLedger is a backend-first, multi-tenant billing and inventory management 
system built with Django and Django REST Framework. It serves wholesale 
distributors who purchase products from suppliers and sell them to retailers.

The system provides REST API endpoints for complete supply chain management, 
including product catalog, inventory tracking, purchase orders, sales, FIFO 
costing, payment processing, and invoice generation.

Tech Stack: Python, Django, Django REST Framework, PostgreSQL, JWT Auth, 
WeasyPrint (PDF generation), Swagger/OpenAPI documentation

Repository: https://github.com/iamshammas/stockledger

PROBLEM SOLVED:
Many wholesale businesses still manage inventory and finances manually using 
notebooks and spreadsheets, leading to:
  • Unknown inventory levels
  • Inaccurate profit calculations
  • Lost purchase history
  • No payment tracking
  • Manual invoice generation errors
  • Inability to manage retailer credits

StockLedger digitizes these operations while ensuring accounting accuracy 
through FIFO inventory costing and comprehensive audit trails.

TECHNICAL ARCHITECTURE:

Layered Architecture:
  Client (Web/Mobile) 
    ↓
  ViewSets (HTTP Layer)
    ↓
  Serializers (Validation & Serialization)
    ↓
  Service Layer (Business Logic)
    ↓
  Django ORM & Models
    ↓
  PostgreSQL Database

Key Design Principles:
  • Clean Separation of Concerns - Business logic isolated in Service Layer
  • Transaction Safety - All multi-step operations use database transactions
  • Audit Trail - Complete history of all inventory and financial movements
  • Data Integrity - Foreign keys, constraints, and referential integrity
  • Tenant Isolation - Every record belongs to exactly one tenant
  • Framework Independence - Services can be tested without Django/HTTP

Technology Stack:
  Backend: Python 3.x, Django 6.0.7
  API Framework: Django REST Framework 3.17.1
  Database: PostgreSQL (with psycopg3 driver)
  Authentication: JWT (SimpleJWT 5.5.1)
  PDF Generation: WeasyPrint 69.0
  API Documentation: drf-spectacular 0.30.0
  Environment: Python Dotenv for configuration

KEY BUSINESS RULES IMPLEMENTED:

1. FIFO Inventory Costing
   - First purchased products are first to be sold
   - Cost is calculated based on chronological purchase order
   - FIFO layer tracking with remaining quantities and prices
   - Automatic recalculation on invoice edits

2. Multi-Tenant Data Isolation
   - Every record belongs to exactly one tenant
   - Queries automatically filtered to current tenant
   - Cross-tenant access prevention at serializer and view level
   - Tenant determined from authenticated user, never from request

3. Editable Invoices with Consistency
   - Invoice quantities can be modified after creation
   - System automatically reverses original StockMovement entries
   - New quantities trigger fresh FIFO allocation
   - Inventory remains accurate through edit cycle

4. Partial Payment Support
   - Invoices can receive multiple partial payments
   - Overpayments automatically converted to retailer credit
   - Retailer credit can be applied to future invoices
   - Complete payment history per sale

5. Transaction Safety
   - All multi-table operations wrapped in database transactions
   - ACID compliance for financial operations
   - Rollback on any validation failure
   - No orphaned records or inconsistent states

6. Audit Trail
   - Complete StockMovement history (immutable)
   - Payment history with methods and dates
   - Retailer credit ledger (all transactions tracked)
   - Inventory adjustment tracking
   - Sale modification history
